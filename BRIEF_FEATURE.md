# Business Brief Feature — Design Document

## Understanding Summary

- **What:** When a user clicks a lead in the dashboard, the existing slide-over Sheet expands to include a new "Business Brief" section with three labelled parts: `About`, `Pain Points`, and `Why They're a Fit`
- **Why:** Agency staff need context before calling a lead — who the business is and exactly why they need the agency's services — without doing their own research
- **Who:** Agency staff using the leadgen dashboard to work leads
- **How:** Generated by Gemini, grounded in real data fetched from the business's website (httpx), Serper.dev search results, and existing reviews/praise/complaints already in the database
- **When:** Lazy + cached — generated on first click (~3–5s wait), stored in the database, served instantly on all future clicks
- **Fallback:** If data sources are missing or unavailable, show whatever sections could be populated and flag the gaps clearly — partial truth over invented content

## Explicit Non-Goals (this iteration)

- No outreach script or talking points
- No contact actions (copy phone, email template, WhatsApp draft)
- No lead timeline or activity log
- No notes upgrade
- No pre-generation at scrape time
- No real-time SSE streaming

---

## Assumptions

1. `leads_history.website` stores the business website URL (may be NULL)
2. Serper.dev has sufficient quota headroom for on-demand searches
3. The `leads_history` table accepts a new nullable `brief` TEXT column via migration
4. 3–5 second generation wait on first click is acceptable to users
5. Brief is permanent — no automatic expiry or regeneration unless explicitly triggered

---

## Architecture

```
User clicks lead in dashboard
        ↓
Sheet opens (existing behaviour)
        ↓
Frontend checks: does lead.brief exist?
    ├── YES → stagger-reveal About → Pain Points → Why They're a Fit
    └── NO  → show skeleton loader
              call POST /api/dashboard/leads/{id}/brief
                      ↓
              Backend agent runs:
              1. httpx fetch business website (if URL exists)
              2. Serper search "{name} {city} reviews services"
              3. Gemini synthesises → returns structured JSON
                      ↓
              Store brief JSON in leads_history.brief (Neon DB)
                      ↓
              Return brief to frontend
                      ↓
              Stagger-reveal About → Pain Points → Why They're a Fit
```

## Backend

### 1. Database Migration

**File:** `utils/db.py` — inside existing `run_migrations()`

```sql
ALTER TABLE leads_history
ADD COLUMN IF NOT EXISTS brief TEXT DEFAULT NULL;
```

Idempotent — safe to run on every startup.

### 2. Brief Generation Agent

**File:** `utils/brief.py` (new)

**Function signature:**
```python
async def generate_brief(lead: dict) -> dict
```

**Step 1 — Fetch website**
- If `lead["website"]` exists: `httpx.get(url, timeout=5)`
- Strip HTML tags, truncate to first 2000 characters
- On failure/timeout/missing: `website_text = None`, append `"website_not_found"` to `data_flags`

**Step 2 — Serper search**
- Query: `"{business_name} {city} reviews services"`
- Extract top 2 organic snippets + knowledge graph summary if present
- On failure: `search_text = None`, append `"search_unavailable"` to `data_flags`

**Step 3 — Gemini generation**
- Build prompt from all available data:
  - Always: name, category, rating, review count, praise summary, complaints summary
  - Conditionally: website text, search snippets
- Return strict JSON:

```json
{
  "about": "2–3 factual sentences about who they are and what they do.",
  "pain_points": "2–3 sentences based only on evidence from sources above.",
  "why_a_fit": "2–3 sentences grounded in the pain points identified.",
  "data_flags": []
}
```

- On invalid JSON from Gemini: retry once, then return structured error state

### 3. API Endpoint

**File:** `routers/leads.py` (additive — new route in existing file)

```
POST /dashboard/leads/{lead_id}/brief
Auth: X-API-Key header (existing auth unchanged)
```

**Logic:**
1. Fetch lead from `leads_history` by `lead_id` → 404 if not found
2. If `lead.brief` is already populated → return immediately (cache hit)
3. Call `generate_brief(lead)`
4. `UPDATE leads_history SET brief = %s WHERE id = %s`
5. Return brief with `cached: false`

**Response shape:**
```json
{
  "brief": {
    "about": "...",
    "pain_points": "...",
    "why_a_fit": "...",
    "data_flags": []
  },
  "cached": false
}
```

**Error states:**
- `404` — lead not found
- `422` — lead has no name/city (cannot generate)
- `503` — Gemini unavailable

```typescript
  api.post(`/leads/${leadId}/brief`)
```

### 3. Sheet Expansion

**File:** `app/dashboard/leads/page.tsx`

**New state:**
```typescript
const [brief, setBrief] = useState<Brief | null>(null)
const [briefLoading, setBriefLoading] = useState(false)
const [briefVisible, setBriefVisible] = useState<string[]>([])
```

**On sheet open:**
```
If lead.brief exists → go to stagger reveal
If not → setBriefLoading(true) → POST /brief → setBrief → stagger reveal
```

**Stagger reveal timing:**
- 0ms   → 'about' appears
- 400ms → 'pain_points' appears
- 800ms → 'why_a_fit' appears

**Animation:** `opacity: 0 → 1` + `translateY(8px → 0)` over 300ms — pure Tailwind transitions, no animation library.

**Visual layout inside Sheet:**
```
─────────────────────────────
 BUSINESS BRIEF
─────────────────────────────
 About
 [2–3 sentences — fade in]

 Pain Points                  ← +400ms
 [2–3 sentences — fade in]

 Why They're a Fit            ← +800ms
 [2–3 sentences — fade in]

 ⚠ Website could not be found ← data_flags (muted text, if any)
─────────────────────────────
```

**Skeleton state** (while loading):
- Three grey pulsing bars matching final layout — no layout shift on reveal

## Decision Log

| # | Decision | Alternatives Considered | Why |
|---|----------|------------------------|-----|
| 1 | Bio + Pain Points only | Full bio + pains + script | Tight scope; script is a future iteration |
| 2 | Expand existing Sheet | New page, separate modal | Sheet already exists; more can be added later |
| 3 | Gemini + website + Serper | Gemini only, Google Places only | Maximum truthfulness from real public data; all sources already paid for |
| 4 | Lazy + cached | Pre-generate at scrape time, regenerate every click | No wasted generation; zero repeat latency |
| 5 | Structured sections: About / Pain Points / Why They're a Fit | Two paragraphs, bullet card | Most scannable before a call |
| 6 | Show available + flag gaps | Block generation, show confidence score | Partial truth is useful; blocking frustrates users |
| 7 | Simple on-demand endpoint | LangGraph mini-pipeline, full SSE streaming | Fits existing stack; no new patterns; ships fast |
| 8 | Simulated stagger reveal | Pure skeleton loader, real SSE streaming | Progressive feel without streaming infrastructure |
| 9 | Single `brief` TEXT column in `leads_history` | Separate `lead_briefs` table | Additive, simple, no joins needed; 1:1 with lead |
